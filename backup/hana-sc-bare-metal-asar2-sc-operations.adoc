[role="lead"]
この章では、SnapCenter を使用したバックアップ、リストア、リカバリ、SAP システムの更新、および非同期レプリケーション操作について説明します。



[[backup-operations]]
== バックアップ処理

バックアップ操作は、 https://docs.netapp.com/us-en/netapp-solutions-sap/backup/hana-sc-generic-backup-operations.html["SnapCenterでの SAP HANA スナップショットのバックアップ操作について学習します。"]に記載されているのと同じ方法で実行されます。


NOTE: ストレージユニットに整合性グループが設定されていない場合、SnapCenter は最初の Snapshot バックアップ操作で整合性グループと子整合性グループを作成します。次に、HANA データストレージが子整合性グループに割り当てられます。SnapCenter の Snapshot バックアップは、子整合性グループ内に一覧表示されます。

image:hana-sc-bare-metal-asar2-image-007.png["width=601,height=191"]

image:hana-sc-bare-metal-asar2-image-008.png["width=601,height=205"]



[[restore-and-recovery]]
== リストアとリカバリ

復元および復旧操作は、前述の方法と同様に実行されます https://docs.netapp.com/us-en/netapp-solutions-sap/backup/hana-sc-generic-restore.html["SnapCenterを使用した SAP HANA データベースの復元とリカバリ"]。



[[asynchronous-storage-replication]]
== 非同期ストレージ レプリケーション

HANAデータボリュームについては、非同期ストレージ レプリケーションが設定されています。

image:hana-sc-bare-metal-asar2-image-009.png["幅=601、高さ=180"]

レプリケーションは MirrorAndVault ポリシーで設定されています。

image:hana-sc-bare-metal-asar2-image-010.png["width=601,height=206"]

MirrorAndVaultポリシーには、さまざまなSnapMirrorラベルと保持期間が含まれています。

image:hana-sc-bare-metal-asar2-image-011.png["width=601,height=235"]

SnapCenterで、ONTAPのMirrorAndVaultポリシーのSnapMirrorラベル「daily」に一致するポリシーが構成されています。

image:hana-sc-bare-metal-asar2-image-012.png["width=378,height=354"]

ONTAP MirrorAndVault ポリシーを使用する場合、Snapshot バックアップはターゲット ストレージに一度しか存在しないにもかかわらず、SnapCenter では Vault と Mirror のコピーが別々に表示されます。

image:hana-sc-bare-metal-asar2-image-013.png["幅=601、高さ=294"]



[[sap-system-refresh]]
== SAP システムの更新

SnapCenter を使用した SAP システムの更新およびクローニング操作の詳細については、 https://docs.netapp.com/us-en/netapp-solutions-sap/lifecycle/sc-copy-clone-introduction.html["SnapCenter を使用して SAP HANA システムのコピーおよびクローン処理を自動化"]を参照してください。



[[snapcenter-workflow]]
=== SnapCenter ワークフロー

操作の詳細と前提条件については、 https://docs.netapp.com/us-en/netapp-solutions-sap/lifecycle/sc-copy-clone-hana-sys-refresh-with-sc.html#prerequisites-and-limitations["SAP HANAシステムをSnapCenter で更新"]に記載されています。具体的には、最初の更新/クローン操作を実行する前に、ターゲットシステムを SnapCenter に追加する必要があります。

クローン作成ワークフローの最初のステップでは、ターゲットホストとターゲットSIDを指定する必要があります。

image:hana-sc-bare-metal-asar2-image-014.png["width=333,height=313"]

プロトコルの選択は「FCP」でなければなりません。

image:hana-sc-bare-metal-asar2-image-015.png["width=334,height=312"]

必要に応じて、sc-system-refresh.sh スクリプトを追加することで、復旧操作を自動化できます。

image:hana-sc-bare-metal-asar2-image-016.png["width=352,height=331"]

以下のスクリーンショットは、クローン作成ワークフローのジョブログを示しています。

image:hana-sc-bare-metal-asar2-image-017.png["width=379,height=468"]
